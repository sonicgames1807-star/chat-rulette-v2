# Случай — прототип чат-рулетки

## Самый простой запуск на Windows

1. Установи Node.js 20 или новее.
2. Распакуй архив и запусти `start.bat` из папки `roulette-app`.
3. Не закрывай окно сервера. Открой `http://localhost:4173` — стартовый скрипт попробует открыть страницу сам.
4. Открой адрес во второй вкладке, чтобы проверить случайный подбор между двумя пользователями.

Для Linux/macOS: `./start.sh`. Вручную: `npm install`, `npm run build`, `npm test`, `npm start`.

**Не открывай `index.html` двойным щелчком**: страница должна обслуживаться Node-сервером, иначе WebSocket-чат не подключится.

## Важно: локально и в интернете — разные вещи

Архив запускает сервер на твоём компьютере. Локальный адрес доступен только тебе; другие люди из интернета к нему не подключатся. Чтобы общаться с незнакомцами онлайн, разверни приложение на VPS/сервере с публичным доменом и HTTPS. В комплекте есть `Dockerfile`, `docker-compose.yml` и Caddy-конфигурация для HTTPS/WSS. В DNS домена укажи IP сервера, открой порты 80 и 443, скопируй `.env.example` в `.env`, укажи настоящий `DOMAIN`, затем запусти `docker compose up -d --build`.

Голосовая связь между разными сетями может не пройти через один STUN. Для production подключи TURN-сервер: укажи `TURN_URLS` и `TURN_SHARED_SECRET` в `.env`; сервер выдаёт короткоживущие TURN-учётные данные. TURN-сервер и его секрет нужно настроить отдельно. Локальный voice-тест на localhost не заменяет проверку из разных сетей.

Адаптивное веб-приложение для случайного текстового и голосового общения. UI и копирайт оригинальные. В демо работают matchmaking среди подключённых клиентов, текстовые сообщения через WebSocket, одноразовая очередь, жалобы без сохранения текста переписки и голосовая передача через WebRTC.

## Запуск

Требуется Node.js 20+.

```bash
npm install
npm run build
npm test
npm start
```

Откройте http://localhost:4173 в двух окнах/вкладках и начните поиск с каждой стороны. Для теста голосового режима разрешите микрофон. На localhost современные браузеры считают контекст безопасным.

## Что реально работает в этой демо-версии

- Гостевой вход без регистрации; возрастной диапазон используется как добровольная настройка, а не дата рождения.
- Фильтры по режиму, полу, диапазону возраста, языку и общим темам; сервер проверяет взаимную совместимость.
- Случайный подбор из доступной очереди; если второго совместимого участника нет, поиск честно остаётся в ожидании.
- Чат реального времени между двумя подключёнными браузерами.
- Голосовой звонок WebRTC с запросом микрофона только после нажатия старта в голосовом режиме.
- Выход, следующий собеседник, блокировка на время соединения и форма жалобы.
- Мобильная раскладка, клавиатурная навигация, reduced motion и подписи элементов для screen reader.

## Ограничения и безопасность

Это MVP-прототип, не production-сервис. Очередь, комнаты, блокировки и агрегированные категории жалоб существуют только в памяти процесса и сбрасываются при перезапуске. База данных, Redis, настоящая служба модерации, подтверждение возраста/личности и постоянное управление блокировками пока не подключены. Самостоятельная отметка 18+ не проверяет возраст.

Текст чата сервер не сохраняет: сообщение пересылается собеседнику и остаётся только в состоянии открытой вкладки. Голосовой поток не записывается приложением; он передаётся браузер-браузер. IP-адреса могут быть видны хостинг-провайдеру и участникам сетевого обмена. В демо жалоба — только категория в оперативной памяти и не поступает модераторам.

Для публичного запуска обязательны: юридическая проверка стран работы и возрастного контроля, real age assurance для продукта 18+, оценка угроз и приватности, политика хранения/удаления данных, настоящая модерация и on-call-процессы, защита от злоупотреблений, HTTPS/WSS, TURN-инфраструктура для WebRTC за NAT, лимиты соединений и нагрузочные тесты. Встроенный STUN-сервер предназначен только для демонстрации; production-конфигурация должна использовать управляемые STUN/TURN-серверы.

## Структура

- `src/main.jsx` — React UI и клиентская логика.
- `src/styles.css` — responsive-дизайн.
- `server.mjs` — HTTP + WebSocket matchmaking/signaling.
- `build.mjs` — локальная сборка через esbuild.
- `test/matchmaking.test.mjs` — интеграционная проверка очереди, сообщений и блокировки.
- `index.html` — точка входа.

## Настройки

- `PORT` — порт HTTP-сервера (по умолчанию `4173`).
- `GET /api/health` — состояние демо-сервера без пользовательского содержимого.
